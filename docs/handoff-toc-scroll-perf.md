# Handoff: ToC scroll indicator + perf work (ветка `experiment/scroll-glide-guard`, сентябрь 2026)

Цель ветки: индикатор активного заголовка в ToC, идущий за текстом **живьём даже во время быстрых scroll-фликов**, без форсированных style/layout reflow в скролл-кадре; плюс профайлинг остаточных recalc и авто-разворот секций ToC в реальном времени.

Состояние: **незакоммичено** (см. в конце). Build/lint/tests — зелёные (158/158).

---

## Ключевые инварианты — НЕ нарушать

- **Readless**: никаких геометрия-чтений (`offsetTop`, `getBoundingClientRect`, `scrollTop`, `offsetHeight`) внутри scroll-обработчиков и IO-макротасок. `runFrame` кэширует `getScrollTop()`/`getClientHeight()` раз в кадр; `panelScrollTop` приходит из scroll-обработчика панели и кэшируется после каждой внутренней записи скролла.
- **Пилюля двигается только `transform: translate3d`** — никогда `top`/`left`. Запись top/left переинвалидирует layout каждый раз (так было до ветки: «Recalculate style ~600-700 элементов» в каждом кадре).
- **Виртуализация**: строки ToC существуют в DOM только в узком окне (~viewport + OVERSCAN). «Свернуть» секцию = пересобрать виртуальный список в JS. CSS-свёртка (`display:none`) неприменима — нельзя скрыть то, чего нет в DOM (пришлось бы держать все строки, для тысяч заголовков это сотни КБ DOM + layout). CSS внутри книги работает, потому что секции контента всегда полностью смонтированы.
- **Рефлоу панели запирается контейнингом**: `bv-contain-layout` на `containerEl`.
- Регистрацию имен (command id, классы) после релиза не менять.

## Что сделано в этой ветке

### 1. Живой transform-pill (индикатор активной строки)
- Один элемент `.bv-toc-highlight` — ребёнок spacer-элемента (`state.highlightHost`, ставит `window.mount`, снимает teardown). Позиция — только `transform: translate3d(indent + 4px, top + 2px, 0)`; ширина — CSS-классы по уровню `bv-toc-highlight-level-1..6` = `calc(100% - 8/20/32/44/56/68px)`; скрытие — `translate3d(0, -99999px, 0)`.
- Движение коалицуется в один кадр: scroll-обработчик панели шлёт `positionSource` frame-callback, `onFrameTick(spy)` выполняется раз за rAF (`tickScheduled`), все чтения — из кадрового кэша (`getScrollTop()/getClientHeight()`), без layout-floor.
- Файлы: `src/toc/spy.ts`, `src/toc/state.ts` (highlightHost), `src/toc/window.ts` (mount: highlightHost = spacerEl), `src/styles/styles.css` (~511-536), `src/toc/navigation.ts` (клик по строке → `applyHighlightNow`, «применить сразу»).

### 2. Геометрия пилюли («двойной инсет», фикс замеченного бага)
- Симптом: пилюля смещена вниз/вправо, величина смещения зависела от зума.
- Причина: в CSS остались `top:2px; left:4px` **И** transform добавлял `+2/+4` → итого `(top+4px, indent+8px)`, смещение нелинейно масштабировалось ансестор-зумом.
- Фикс: CSS `.bv-toc-highlight { top:0; left:0 }`; **все** инсеты несёт transform (масштабируются тем же зумом, что и фикс 26px строки). Width-классы изначально были под полный инсет (indent+4 слева, 4 справа) — их не трогали. Пользователь подтвердил геометрию на нескольких зумах.

### 3. Профайлинг остаточных recalc — закрытая ветка (выводы)
- Три источника «Recalculate style»:
  - `applyHighlight` — ~12 элементов, дешёвый, неустраним (смена `is-active`).
  - `loadSection` (mount большой секции) — ~587-1383 элементов; реальный монт DoOf ≈ 38–40ms на 1411 элементов.
  - `unloadSection` (детатч) — те же ~600 элементов на каждый выход секции из окна загрузки.
- **Статистика селекторов в DevTools раздувает длительность в ~50–270×** (замер: 7–8.5мс/элемент со включённой статистикой против ~28µс без). Годна только для *рейтинга*, не для абсолюта; для абсолюта мерить при выключенной статистике.
- Топ mount-recalc на DoOf — **core-правила Obsidian**: `div:has(:is(h1..h4)):has(+ div > .callout[data-callout*="list"]) :is(h1..h4)...`. Наш CSS ≈ **0% вклада** → дальнейшая чистка наших селекторов бессмысленна (выход на асимптоту Obsidian core). Вклад нашего CSS ≈ 0 даже при включённой статистике.
- **Структурные решения, которые НЕ трогать без новых замеров:**
  - `content-visibility: visible` на `.book-section-absolute` (styles.css:40-46). `CV:auto` ломает измерение высоты секций.
  - Не откладывать анлоады: DOM рос → multi-second lag после длинных скроллов (комментарий `SectionPool.processIoPending` ~1496).
  - Не гейтить маунты больших секций жестом: мгновенный «поп-ин» секции с плейсхолдерами неприемлем (комментарий `drainQueue` ~1392).
- Сделанные правки: удалены 4 полностью дублирующих правила `[class*="el-"]:first-child/:last-child *` (дубликаты `:first-child *` / `:last-child *`) — вычисляемые стили идентичны, селекторное дублирование убирает recalc-время на этапе match.

### 4. Авто-разворот секций ToC — теперь LIVE (фикс UX-бага)
- Симптом (пользователь счёл багом): во время скролла ToC **не раскрывал** новую секцию; индикатор работал только на уровне, открытом последним; раскрытие наступало после остановки скролла.
- Причина: `scheduleApplyVisibility` откладывал `applyVisibility` на settle-бит (50мс тишины, само-продлевающийся во время глисса). Виртуальные offset'ы оставались от старой раскладки → для ряда цели не было → пилюля не ложилась.
- Фикс: в блоке active-path в `onScrollTick` (`spy.ts`) `s.applyVisibility()` вызывается** сразу в scroll-кадре**, и сразу после ребилда — `keepActiveInView(highlightIndex)` (offset'ы сменились, панель не должна отставать на кадр). Удалены `scheduleApplyVisibility`, `visibilityRafId`, `APPLY_VISIBILITY_SETTLE_MS`.
- Оправдание перфа: отложка вводилась, когда ребилд «пересоздавал ~1000 элементов DOM заново» — это было **до** переработки на переиспользование строк. Теперь ребилд инкрементален.
- `window.ts`: реконсиляция переведена с O(rows²)-скана (`for present { … }` на каждый ряд) на **O(rows) карту** `byKey: "kind:data-index"` (`file` и `heading` делят числовое пространство индексов — ключ обязателен с префиксом), убирание — мутирующим `take()`.
- **Открытый риск**: при очень быстрых длинных фликах частые раскрытия теоретически могут дать подёргивание панели. Если появится — промежуточный вариант: раскрывать live, а схлопывание (`only-expand`/`collapse-rest`) батчить на settle. В режиме `disabled` поведение не меняется (activePath не пишется).

## Смежные знания (контекст)

- В панели редактирования/чтения ToC — одно и то же состояние; пилюля едина.
- `.bv-toc-heading` строки — фикс 26px (`line-height:22px`, `padding:2px 8px`) — зум согласуется.
- Скрипт монтирует pyлю сразу после первого `applyVisibility`; `rowByEntry` пуст до первого применения (это использовалось как «первый вызов должен быть синхронным» в старом settle-коде).
- После ребилда DOM окна `onRowsRendered → reapplyHighlight(visibleAncestor(activeEntryIndex, mode!=='disabled'))` заново накладывает пилюлю (старый активный узел мог быть детачен).
- При редактировании любой грязи, ложащейся на layout: путь чтения в кадре должен опираться на кэши, а не на живые rect'ы; если когда-нибудь вернёшь settle-батчинг — верни и принудительный flush (`void containerEl.offsetHeight`) в вызове ребилда, чтобы следующий ввод не поймал reflow от свежей пересборки.
- GPU-слой обязателен: `will-change: transform` на пилюле (она перерисовывается в каждом скролл-кадре).
